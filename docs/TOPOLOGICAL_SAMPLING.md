# User-requested topological sampling — October 5, 2026

Implemented `experiments/topological_support_sampling.py`: zero-dimensional persistence via minimum-spanning-tree merge lengths. Cut the seven longest merge edges into eight components, select each component's medoid, then allocate remaining support slots in rounds using farthest coverage. This combines established H0 connectivity with geometric coverage; it does not calculate loops, higher homology or a new topology theorem.

Primary backing: [Chen et al., TAG-ML 2022](https://proceedings.mlr.press/v196/chen22b/chen22b.pdf) describes the MST/H0 connection; [Chen et al., AISTATS 2019](https://proceedings.mlr.press/v89/chen19g.html) establishes prior topological learning methods. Neither source validates this particular sampling heuristic or its predictive advantage. No novelty claim follows from adding topology.

Use Wine's original fitting partition only. For each color and seeds 816001-816003, select a 256-row unlabeled pool and compare 64 topology-selected rows with 64 uniformly selected rows. Both methods receive the same pool and fit-feature median/IQR scaling, clipped at +/-5. Scaling sees all fitting covariates; those feature accesses are explicitly counted. The selection API takes features only and never parses quality labels. Its fixed eight-component choice is not tuned to predictive outcomes.

Saved indices make this a usable support-selection component. This run checks geometry, unique selection, a two-component fixture and raw source hashes only: zero new model fits, labels requested or prediction evaluations. Geometry coverage is not evidence of better labels, calibration or prediction. Outliers, arbitrary distance scaling and connectivity unrelated to the target can all hurt selection; equal merge lengths have no special semantic interpretation.
